# 계획 기능 흐름 개편 개발서

> 작성일: 2026-08-08
> 상태: P1 순서 개편 검증 완료 · 기존 사용 경험을 근거로 P3 판정 진행
> 대상: Notion Clone 계획 탭, Day Planner, 루틴, 주기 노트, HTML 내보내기
> 핵심 결정: 기능을 먼저 개조하지 않는다. 기존 기능의 노출 순서와 사용 흐름을 먼저 개편하고, 실제 사용에서 확인된 불편만 근거로 기능을 추가·축소·삭제한다.

---

## 1. 배경

현재 계획 기능은 일간·주간·월간·분기·연간 노트를 중심으로 구성되어 있다. 그러나 실제 사용에서는 다음과 같은 차이가 확인되었다.

- 루틴 생성과 Day Planner 타임라인은 만족도가 높다.
- 타임라인이 포함된 페이지를 HTML로 내보내 iPad에서 보는 흐름은 계속 유지할 가치가 높다.
- 일기 형식의 고정 템플릿은 볼트마다 사용 목적이 달라 자주 사용되지 않는다.
- 월간·분기·연간 노트는 직접 작성하는 빈도가 낮다.
- 계획 탭이 메모 흐름과 분리되어 있어 작성 중 전환 비용이 발생한다.
- 스톡이미지 제작처럼 날짜·이미지·결과가 중요한 기록에는 현재 일기 구조가 맞지 않는다.

따라서 이번 작업에서는 플래너 기능을 새 모델로 즉시 교체하지 않는다. 먼저 생활 관리 전용 볼트에서 기존 기능의 진입 순서와 화면 우선순위를 재배치하고, 일정 기간 실제로 사용한 결과를 다음 개발의 근거로 삼는다.

---

## 2. 최상위 원칙

### 2.1 순서 개편이 기능 개조보다 먼저다

첫 단계에서 허용하는 변경은 다음과 같다.

- 메뉴 순서 변경
- 섹션 묶음 변경
- 자주 쓰는 기능을 상단으로 이동
- 사용 빈도가 낮은 기능을 접힌 보조 영역으로 이동
- 이름과 안내 문구 개선
- 기존 기능으로 이동하는 단축 진입점 추가

첫 단계에서 하지 않는 변경은 다음과 같다.

- 새로운 기록 블록 추가
- 통합 캘린더 데이터 모델 추가
- Day Planner 저장 형식 변경
- 루틴 저장 형식 변경
- 월간·분기·연간 블록 삭제
- 기존 주기 노트 자동 변환
- HTML 출력 구조 변경

### 2.2 기존 데이터는 보존한다

- 기존 `dayplanner`, `weekplanner`, `weeklyplanner`, `routinematrix`, `monthlycalendar`, `quarterlyplanner`, `yearlyplanner` 블록을 삭제하지 않는다.
- 기존 일간·주간·월간·분기·연간 노트는 계속 열고 편집할 수 있어야 한다.
- 기존 루틴 파일과 90일 초과 일정 아카이브를 유지한다.
- 사용 빈도가 낮은 기능도 즉시 제거하지 않고 먼저 보조 영역으로 이동한다.
- 삭제가 필요해지더라도 읽기 호환과 복구 경로가 준비되기 전에는 실행하지 않는다.

### 2.3 만족도가 높은 기능은 보호한다

다음 기능은 보호 대상이다.

- 루틴 생성·수정·요일 지정
- 루틴의 오늘 일정 적용
- Day Planner 타임라인
- 일정 생성·완료·이동·시간 조절
- 주간 타임라인
- 루틴 달성 매트릭스
- 페이지 HTML 내보내기에서 플래너를 시각적으로 확인하는 기능
- iPad 브라우저에서 내보낸 HTML을 열람하는 흐름
- 기존 플래너 데이터 내보내기

보호 대상은 흐름 개편 중 동작과 출력 결과가 달라지지 않아야 한다.

### 2.4 볼트 하나에서 먼저 시험한다

첫 적용 대상은 별도의 `생활 관리` 볼트로 한다.

- 다른 작업 볼트의 플래너 사용 흐름에 영향을 주지 않는다.
- 생활 습관, 해야 할 일, 루틴, 일정, 회고를 실제로 기록한다.
- 최소 2주 동안 사용한 뒤 다음 기능을 결정한다.
- 스톡이미지 볼트 등의 적용은 생활 관리 볼트에서 흐름이 검증된 뒤 판단한다.

## 3. 현재 기능과 처리 방침

| 기능 | 현재 역할 | 1차 처리 | 장기 후보 |
|---|---|---|---|
| Day Planner | 날짜별 일정 작성과 타임라인 표시 | 최상위 핵심 기능으로 이동 | 날짜 데이터 통합 시 일정 제공자 역할 |

| Day Planner 패널 | 메모를 보면서 일정 확인·빠른 추가 | 접근성을 높임 | `오늘` 패널의 기반 후보 |
| 주간 타임라인 | 여러 날짜의 일정 확인·이동 | 두 번째 우선순위로 유지 | 통합 날짜 보기를 사용하도록 확장 가능 |
| 루틴 매트릭스 | 루틴 완료율 확인 | 두 번째 우선순위로 유지 | 월간·분기 보고서의 데이터 원천 후보 |
| 월간 캘린더 | 월간 날짜 이동과 일간 노트 연결 | 보조 보기로 이동 | 통합 캘린더 후보 |
| 분기 플래너 | 목표·달력·루틴 히트맵 | 접힌 `돌아보기` 영역으로 이동 | 자동 분기 보고서 후보 |
| 연간 플래너 | 연간 목표·월별 현황·루틴 히트맵 | 접힌 `돌아보기` 영역으로 이동 | 자동 연간 보고서 후보 |
| 일간 노트 | 고정 템플릿 기반의 하루 기록 | 기존 생성 기능 유지 | 사용 결과에 따라 간소화 검토 |
| 주기 노트 템플릿 | 일·주·월·분기·연간 문서 생성 | 기존 설정 유지 | 볼트별 템플릿은 관찰 후 검토 |
| HTML 내보내기 | 플래너가 포함된 페이지 공유·열람 | 변경 없이 보호 | 출력 범위 선택은 관찰 후 검토 |

## 4. 1차 목표 정보 구조

계획 탭에서 시간 단위가 아니라 실제 사용 빈도에 따라 기능을 배치한다.

```text
계획
├─ 오늘
│  ├─ 오늘 일정 확인
│  ├─ Day Planner 패널 열기
│  ├─ 오늘의 루틴 확인
│  └─ 오늘 일간 노트 열기
│
├─ 계획하기
│  ├─ Day Planner가 있는 페이지 열기
│  ├─ 루틴 관리
│  └─ 주간 타임라인 열기
│
├─ 살펴보기
│  ├─ 월간 캘린더
│  └─ 루틴 매트릭스
│
└─ 돌아보기  [기본 접힘]
   ├─ 주간 노트
   ├─ 월간 노트
   ├─ 분기 플래너
   └─ 연간 플래너
```

### 4.1 변경 의도

- 앱에서 가장 먼저 보이는 것은 `오늘`이다.
- 타임라인과 루틴은 한 단계 안에서 접근할 수 있어야 한다.
- 월간·분기·연간 문서 생성은 첫 화면에서 사용자를 압박하지 않는다.
- 사용 빈도가 낮은 기능도 삭제하지 않고 `돌아보기`에 보존한다.
- HTML 내보내기는 기존 페이지 도구에서 그대로 사용한다.

### 4.2 이번 단계에서 추가 데이터를 만들지 않는다

`오늘`은 새로운 데이터 형식이 아니다. 기존 기능으로 이동하는 진입점만 묶는다.

- 기존 Day Planner 패널
- 기존 일간 노트 열기
- 기존 루틴 관리 화면
- 기존 주간·월간·분기·연간 노트 열기

따라서 1차 개편은 플래너 데이터 저장과 무관해야 한다.

## 5. 단계별 개발 계획

## P0. 기준선 보존

### 목표

개편 전 기존 기능과 출력 결과를 재현 가능한 기준으로 남긴다.

### 작업

1. 생활 관리 볼트를 기존 UI로 생성한다.
2. 테스트용 루틴 2~3개를 만든다.
3. 하루 일정과 완료 상태를 작성한다.
4. 일정 이동과 시간 조절을 확인한다.
5. 주간 타임라인과 루틴 매트릭스를 확인한다.
6. 플래너가 포함된 페이지를 HTML로 내보낸다.
7. Windows 브라우저와 iPad에서 출력 결과를 확인한다.
8. 기준 화면과 출력 파일을 보존한다.

### 완료 조건

- 루틴 생성과 오늘 적용이 정상 동작한다.
- 타임라인 일정의 생성·완료·이동·시간 조절이 정상 동작한다.
- 새로고침 후 데이터가 유지된다.
- HTML에서 타임라인과 플래너 정보가 보인다.
- 기준 결과가 기록되어 이후 회귀 여부를 비교할 수 있다.

## P1. 계획 탭 순서 개편

### 목표

기능을 변경하지 않고 자주 쓰는 순서로 재배치한다.

### 허용 범위

- `CategorySidebar` 계획 탭의 섹션 순서 변경
- `PeriodicNotesPanel`의 버튼·탭 묶음 변경
- Day Planner 패널 진입 버튼 노출
- `오늘`, `계획하기`, `살펴보기`, `돌아보기` 문구 추가
- `돌아보기` 기본 접힘 상태 추가
- 관련 한국어·영어 번역 추가

### 금지 범위

- 블록 타입 변경
- 저장 JSON 변경
- 백엔드 API 변경
- 기존 루틴·일정 병합 규칙 변경
- HTML 내보내기 변경
- 기록 블록 또는 통합 캘린더 구현

### 완료 조건

- 오늘 일정과 루틴에 한 단계 안으로 접근할 수 있다.
- 월간·분기·연간 기능은 삭제되지 않고 접힌 보조 영역에서 접근할 수 있다.
- 기존 주기 노트 생성 결과가 개편 전과 동일하다.
- 기존 타임라인 조작과 HTML 출력에 회귀가 없다.

## P2. 실제 사용 관찰

### 목표

새 기능 요구를 추측하지 않고 생활 관리 볼트의 실제 사용에서 수집한다.

### 권장 기간

- 최소 14일
- 가능하면 평일과 주말을 모두 포함

단, 이미 해당 기능을 충분히 사용하면서 반복된 불편과 우회 행동이 확인된 경우에는 새 관찰 기간을 강제하지 않는다. 기존 사용 경험, 현재까지 누적된 피드백, 실제로 사용하지 않게 된 이유를 P2 관찰 자료로 인정하고 P3 판정으로 바로 이동한다.

### 매일 기록할 항목

| 항목 | 기록 방법 |
|---|---|
| 오늘 일정에 접근하기 쉬웠는가 | 쉬움 / 보통 / 어려움 |
| 계획 탭을 몇 번 열었는가 | 횟수 |
| 타임라인을 사용했는가 | 예 / 아니요 |
| 루틴을 확인·완료했는가 | 예 / 아니요 |
| 일간 노트를 작성했는가 | 예 / 아니요 |
| 월간·분기·연간 화면을 열었는가 | 화면명과 이유 |
| HTML을 내보냈는가 | 범위와 열람 기기 |
| 다른 메모에 대신 적은 정보가 있는가 | 내용과 이유 |
| 반복된 불편이 있는가 | 한 문장 |

### 관찰 원칙

- 한 번 발생한 불편만으로 기능을 추가하지 않는다.
- 같은 불편이 3회 이상 반복되면 개선 후보로 등록한다.
- 사용하지 않았다는 이유만으로 즉시 삭제하지 않는다.
- 사용하지 않은 이유가 `필요 없음`인지 `찾기 어려움`인지 구분한다.
- 메모나 외부 앱에 우회 기록한 내용은 높은 우선순위 신호로 본다.

### 현재까지 확인된 관찰 결과

다음 내용은 계획 기능을 실제로 사용한 경험에서 반복적으로 확인되었으므로 별도의 14일 재관찰 없이 판정 근거로 사용한다.

- 메모 작성 중 별도의 `계획` 탭으로 이동하는 흐름 자체가 번거롭다.
- 계획 기능의 표시 순서만 바꾸어도 분리된 탭으로 들어가야 하는 불편은 해결되지 않았다.
- 볼트마다 사용 목적이 다른데 일기형 고정 템플릿을 공통으로 사용하기 어렵다.
- 스톡이미지 작업은 어떤 날짜에 어떤 이미지를 제작했는지 기록해야 하지만 현재 일기 구조와 맞지 않는다.
- 월간·분기·연간 노트는 직접 작성하는 방식으로 거의 사용하지 않는다.
- 반대로 루틴 만들기, Day Planner 타임라인, HTML 출력과 iPad 열람은 계속 유지하고 싶은 기능이다.

따라서 현재 핵심 문제는 메뉴의 순서가 아니라 `계획 기능이 메모 흐름과 분리되어 있는 구조`로 판정한다.

## P3. 사용 결과 판정

### 목표

관찰 결과를 `유지`, `순서 조정`, `기능 개선`, `새 기능`, `숨김`, `폐기 검토`로 분류한다.

| 관찰 결과 | 결정 |
|---|---|
| 자주 사용하고 불편이 없음 | 유지 |
| 자주 사용하지만 찾기 어려움 | 순서 또는 진입점 조정 |
| 자주 사용하지만 동일 불편이 반복됨 | 최소 기능 개선 |
| 필요한 정보를 다른 메모·앱에 반복 기록함 | 새 기능 후보 |
| 사용하지 않지만 유지 비용이 낮음 | 보조 영역에 유지 |
| 사용하지 않고 UI 복잡도를 높임 | 기본 숨김 |
| 사용하지 않고 유지 비용·오류 위험이 높음 | 호환 계획 후 폐기 검토 |
| 기존 데이터를 포함함 | 삭제 금지, 마이그레이션 우선 |

### P4-1. 노트 흐름 최소 통합 — 완료

- 노트 탭 최상단에 `오늘 일정 보기` 진입점을 추가했다.
- 진입점은 기존 Day Planner 패널을 열며 새로운 저장 형식이나 API를 만들지 않는다.
- 일정, 타임라인, 루틴은 기존 구현을 그대로 사용한다.
- 계획 탭은 대체 경로 검증이 끝날 때까지 유지한다.
- 타입 검사, 관련 린트, 실제 화면의 버튼 노출과 패널 열기를 확인했다.

### P4-2. 계획 화면 보조 메뉴 이동 — 완료

- 사이드바 상단의 노트·계획 탭 토글을 제거했다.
- 계획 진입점은 사이드바 하단 보조 메뉴의 달력 버튼으로 이동했다.
- 계획 화면에는 노트 목록으로 돌아가는 복귀 버튼을 유지했다.
- 노트 탭의 `오늘 일정 보기`는 주 진입점으로 계속 노출한다.
- 기존 계획 화면, 주기 노트, 캘린더와 플래너 데이터는 삭제하거나 변경하지 않았다.
- 타입 검사, 관련 린트, 보조 메뉴 진입과 노트 복귀 동작을 실제 화면에서 확인했다.

### P4-3. 기록 헤더 블록 — 완료

- 새 중첩 본문을 만들지 않는 `record` 블록을 추가했다.
- 저장 구조는 `{ date, title, kind }`이며 날짜만 필수로 사용한다.
- 제목과 종류는 선택 입력이며, 실제 기록 내용은 뒤따르는 기존 최상위 블록에 작성한다.
- 슬래시 메뉴의 기존 `플래너` 목차에 `기록 헤더`를 추가했다.
- 일반 메모 검색, 마크다운·HTML 출력, 잡지 레이아웃과 템플릿 특수 블록 문법을 연결했다.
- HTML 기록 헤더에는 `record-{blockId}` 앵커를 출력해 다음 캘린더 연결에 사용할 수 있게 했다.
- 타입 검사, 관련 린트, 슬래시 메뉴 노출과 HTML 변환·이스케이프를 검증했다.

### P4-4. 통합 캘린더의 기록 헤더 집계 — 완료

- 모든 일반 메모의 최상위 `record` 블록을 날짜별로 집계한다.
- 기존 페이지 생성일 점 표시는 유지하고, 기록이 있는 날짜에는 주황색 개수 배지를 별도로 표시한다.
- 날짜를 선택하면 기록 종류·제목·원본 페이지가 목록으로 나타난다.
- 기록을 선택하면 원본 페이지를 열고 해당 기록 헤더 위치로 이동한다.
- 기존 일간 노트 생성, 타임라인, 루틴과 플래너 저장 구조는 변경하지 않았다.

다음 구현은 실제 사용 후 기록 종류 필터나 본문 범위 처리 필요성이 확인될 때 결정한다.

### P4-5. 볼트별 기본 템플릿 — 1차 완료

- 기본 템플릿 ID는 전역 설정이 아니라 현재 볼트의 `_templates` 폴더에 저장한다.
- 설정의 템플릿 목록에서 현재 볼트의 새 메모 기본 템플릿을 지정하거나 해제할 수 있다.
- 새 메모 창 최상단에 현재 볼트 기본 템플릿 빠른 생성 항목을 표시한다.
- 빈 페이지와 다른 템플릿 선택 경로는 그대로 유지한다.

### P4-5. 볼트별 기능 표시 설정 — 2차 1단계 완료

- 설정에 `볼트 기능` 탭을 추가하고 현재 볼트 루트의 `_vault_preferences.json`에 저장한다.
- `오늘 일정 보기`, 사이드바 하단 `계획`, 계획 허브의 `돌아보기` 진입점을 볼트마다 표시하거나 숨길 수 있다.
- 설정 파일이 없거나 손상된 볼트는 모든 기능을 표시하는 기본값으로 복구한다.
- 표시를 꺼도 기존 플래너·기록 블록과 저장 데이터는 삭제하거나 변경하지 않는다.
- 1단계에서는 자주 보이는 세 진입점을 먼저 분리하고, 나머지 계획 기능은 2단계에서 같은 설정 구조로 확장한다.

### P4-5. 볼트별 기능 표시 설정 — 2차 2단계 완료

- `통합 캘린더`, `주간 타임라인`, `루틴 관리`, `슬래시 메뉴 플래너 블록` 표시 설정을 추가한다.
- 타임라인과 루틴을 모두 끄면 계획 허브의 빈 `계획하기` 영역도 함께 숨긴다.
- 슬래시 설정을 끄면 플래너 목차와 검색 결과의 신규 삽입 항목만 숨기고 기존 플래너 블록은 유지한다.
- 전역 캘린더 플러그인과 볼트별 캘린더 설정이 모두 켜진 경우에만 통합 캘린더를 표시한다.

### P4-6. 기록 헤더 기반 월간 자동 요약 — 1차 완료

- 계획 허브의 `살펴보기`에 읽기 전용 월간 기록 요약을 추가한다.
- 선택한 달의 기록 일수·전체 기록 수·종류별 개수를 자동 집계한다.
- 날짜별 기록 목록에서 원본 메모의 기록 헤더 위치로 이동할 수 있다.
- 이전·다음 달을 탐색할 수 있지만 월간 노트 페이지를 자동 생성하지 않는다.
- 기존 월간·분기·연간 노트와 플래너 저장 데이터는 변경하지 않는다.

### P4-6. 분기·연간 자동 요약 — 2차 완료

- 월간 요약 카드에 `월간 / 분기 / 연간` 전환을 추가한다.
- 현재 날짜가 속한 분기와 연도를 기준으로 기록 일수·전체 기록 수·종류별 개수를 집계한다.
- 이전·다음 버튼은 선택한 단위에 맞춰 한 달·한 분기·한 해씩 이동한다.
- 세 기간 모두 날짜별 기록과 원본 기록 이동을 같은 방식으로 제공한다.

### P4-7. 일정·루틴 실행 통계 — 1차 완료

- 월간·분기·연간 기록 요약에 일정 완료 수·완료율과 완료 시간·계획 시간을 함께 표시한다.
- 90일 이내의 플래너 블록 데이터와 이전 기록 아카이브를 합치고, 같은 날짜의 같은 일정 ID는 한 번만 집계한다.
- 새 수동 일정과 루틴 적용 일정에 생성 출처를 저장해 이후 루틴 실행률을 정확히 계산한다.
- 기존 일정은 출처를 추정하거나 변경하지 않으며 일반 일정 통계에만 포함한다.
- 통계는 읽기 전용이며 기존 월간·분기·연간 노트와 플래너 기록을 자동 생성하거나 수정하지 않는다.

### P4-8. 기록 범위 HTML 출력 — 1차 완료

- 각 기록 헤더에서 `이 기록만 HTML로 저장`할 수 있다.
- 출력 범위는 선택한 최상위 기록 헤더부터 다음 기록 헤더 직전까지이며, 마지막 기록은 페이지 끝까지 포함한다.
- 범위 안의 이미지·일정표 등은 기존 HTML 변환과 단일 파일 임베딩 방식을 그대로 사용한다.
- 기록 날짜를 Day Planner 표시 날짜로 전달해 범위 안의 일정표도 같은 날짜를 기준으로 출력한다.
- 기존 페이지 전체 HTML 출력은 기본 동작과 결과를 변경하지 않는다.

### P4-9. 최종 회귀 검증 — 완료

- 기록·기간 집계 6개, 저장 직렬화 2개, 기록·일정 HTML 출력 5개 검사를 통과했다.
- 계획 허브, 오늘 일정 패널, 월간·분기·연간 자동 요약과 기존 일간·주간 노트 진입을 실제 화면에서 확인했다.
- 기존 일간·주간 노트를 다시 열었을 때 일정과 블록 수가 유지되는 것을 확인했다.
- 구버전 주간 노트의 빈 체크리스트와 날씨는 최초 열기에서 한 번 정규화됐으며, 이후 재열기에서는 revision이 증가하지 않았다.
- 전체 페이지와 기록 범위 HTML API, 잘못된 기록 헤더의 404 응답과 Day Planner 일정·루틴 기록 출력을 확인했다.
- `vault_config.json`과 다른 볼트의 페이지·플래너 데이터는 변경 대상으로 사용하지 않았다.

### P4-10. 오늘·이번 주 통합 HTML — 1차 완료

- 계획 허브의 오늘 영역에서 `오늘 HTML`과 `이번 주 HTML`을 바로 저장할 수 있다.
- 현재 볼트 전체의 기간 내 기록 헤더 본문과 Day Planner 일정을 날짜별로 한 파일에 모은다.
- 같은 날짜·같은 일정 ID는 한 번만 출력하며 기록은 다음 기록 헤더 직전까지만 포함한다.
- 기록 범위 안의 이미지는 기존 base64 임베딩을 재사용해 오프라인 HTML로 유지한다.
- 출력 API는 최대 31일만 허용하며 기존 전체 페이지·현재 기록 HTML API는 변경하지 않는다.

## P4. 근거가 확인된 기능만 개발

P4는 미리 확정하지 않는다. 다음 항목은 모두 가설이며 P2·P3 결과가 있을 때만 개발한다.

### 후보 A. 기록 블록

다음 상황이 반복될 때 검토한다.

- 타임라인 완료만으로 실제 결과를 남기기 부족하다.
- 생활 상태·사진·메모를 다른 일반 메모에 반복해서 적는다.
- 날짜별 결과를 다시 찾기 어렵다.

### 후보 B. 통합 캘린더

다음 상황이 반복될 때 검토한다.

- 일정 외의 날짜 기록도 캘린더에서 보고 싶다.
- 월간 노트를 만들지 않고 날짜별 활동을 확인하고 싶다.
- 같은 내용을 메모와 일간 노트에 중복 작성한다.

### 후보 C. 볼트별 기능 프로필과 템플릿

다음 상황이 반복될 때 검토한다.

- 생활 관리 볼트와 다른 볼트가 서로 다른 플래너 구성을 필요로 한다.
- 전역 템플릿 때문에 볼트 전환 후 불필요한 항목이 나타난다.
- 볼트마다 숨기고 싶은 계획 보기가 분명하다.

### 후보 D. 월간·분기·연간 자동 보고서

다음 상황이 반복될 때 검토한다.

- 직접 작성하는 주기 노트는 사용하지 않지만 활동 통계는 보고 싶다.
- 루틴 달성률 외에 작업·건강·생활 기록의 집계가 필요하다.

### 후보 E. HTML 출력 범위 선택

다음 상황이 반복될 때 검토한다.

- iPad에서 오늘 또는 이번 주 정보만 따로 보고 싶다.
- 출력 시 개인 메모를 제외하고 싶다.
- 타임라인과 루틴 매트릭스를 한 문서로 묶는 작업을 반복한다.

## P5. 기능 축소 또는 폐기

### 원칙

- P2 관찰과 P3 판정 없이 기능을 삭제하지 않는다.
- 기존 데이터가 있는 블록은 렌더링 호환을 유지한다.
- 새 생성만 중단하고 기존 문서는 계속 열 수 있는 `읽기 호환` 단계를 먼저 둔다.
- 내보내기와 백업 방법을 먼저 준비한다.
- 기본 숨김과 완전 삭제를 구분한다.

### 단계

1. 기본 화면에서 숨김
2. 설정에서 다시 표시 가능
3. 새 블록·새 노트 생성 중단
4. 기존 데이터 읽기·편집 유지
5. 대체 기능과 마이그레이션 검증
6. 유지 비용이 명확히 큰 경우에만 코드 제거 검토

## 6. 데이터와 출력 안전 계약

### 저장

- 루틴은 현재 볼트의 `_planner_routines.json`을 계속 사용한다.
- 오래된 일정은 현재 `_planner_archive.json` 흐름을 유지한다.
- Day Planner 블록의 `eventsByDate`와 `reviewByDate` 형식을 변경하지 않는다.
- P1에서는 새로운 볼트 메타데이터 파일을 만들지 않는다.

### HTML 출력

- 플래너가 포함된 기존 페이지의 HTML 구조와 보이는 정보를 유지한다.
- 로컬 이미지 임베딩과 오프라인 열람 동작을 유지한다.
- Windows 브라우저와 iPad에서 같은 기준 파일을 비교한다.
- P1 완료 조건에 HTML 출력 회귀 검사를 포함한다.

### 볼트 안전

- `vault_config.json`을 초기화하거나 계획 기능 설정 파일로 전용하지 않는다.
- 실제 활성 볼트를 확인한 뒤 테스트한다.
- 테스트 일정과 루틴은 생활 관리 볼트에만 생성한다.
- 다른 볼트의 기존 페이지와 플래너 블록을 자동 변경하지 않는다.

## 9. 완료 정의

이번 개선 작업의 성공은 새 기능의 수로 판단하지 않는다.

- 생활 관리 볼트에서 오늘 일정과 루틴에 더 빠르게 접근한다.
- 만족도가 높은 타임라인과 HTML 출력이 그대로 유지된다.
- 사용하지 않는 월간·분기·연간 기능이 첫 화면을 방해하지 않는다.
- 실제 사용 중 전달된 불편과 각 단계의 회귀 검증 결과가 남는다.
- 다음 기능의 추가·숨김·삭제 결정에 실제 사용 근거가 있다.
- 기존 볼트와 기존 플래너 데이터에 손상이 없다.

최종적으로 기록 블록이나 통합 캘린더가 필요하지 않다고 판단되면 만들지 않는 것도 성공으로 본다.
