# 단일 일기 볼트와 날짜별 블록 메모 개발서

> 작성일: 2026-08-23
> 상태: P0~P3 구현 및 자동 검증 완료 · 실제 UI 사용 확인 대기
> 대상: 볼트 설정, 날짜별 일기 메모, 기존 블록 편집기, 일기 달력과 전역 진입점
> 핵심 결정: 앱에서 일기 볼트 하나를 명시적으로 지정하고, 그 볼트 안에서만 날짜별 일기 메모를 생성한다. 일기 한 편은 메모 한 장이며 본문은 기존 블록 편집기를 사용한다.

---

## 1. 목적

자기 전에 생각과 하루의 일을 형식에 얽매이지 않고 쓰되, 업무·자료 메모와 섞이지 않는 일기 공간을 제공한다.

```text
앱 전체
├─ 일반 볼트들
└─ 지정된 일기 볼트 1개
   ├─ 일기 2026-08-23
   ├─ 일기 2026-08-24
   └─ 일기 2026-08-25
```

각 날짜의 일기는 메모 한 장으로 관리한다. 메모 본문에서는 기존 블록 편집기를 그대로 사용하여 문단, 제목, 이미지, 인용, 체크리스트 등을 필요할 때 추가할 수 있다.

이 기능의 성공 기준은 다음과 같다.

```text
일기 볼트가 다른 기록 공간과 명확히 분리됨
→ 오늘 일기를 한 번의 동작으로 엶
→ 빈 문단에서 바로 작성함
→ 필요할 때만 블록 기능을 사용함
→ 같은 날짜에는 일기가 하나만 존재함
```

## 2. 확정된 제품 결정

### 2.1 일기 볼트는 하나만 지정한다

- 앱의 현재 `vaults_root` 안에서 일기 볼트를 하나만 지정할 수 있다.
- 일기 기능의 공식 생성·달력·오늘 진입점은 지정된 볼트에서만 활성화한다.
- 일반 볼트에서 사용자가 직접 `일기`라는 제목의 메모를 만드는 것은 막지 않는다.
- 제한 대상은 앱이 제공하는 공식 날짜별 일기 워크플로우다.

### 2.2 일기 한 편은 날짜별 메모 한 장이다

- 날짜 키는 로컬 날짜의 `YYYY-MM-DD`를 사용한다.
- 신규 제목은 `일기 YYYY-MM-DD` 형식을 사용한다.
- 페이지 제목을 바꾸더라도 일기 정체성이 사라지지 않도록 페이지 역할과 날짜 메타데이터를 함께 저장한다.
- 같은 날짜를 다시 열면 기존 페이지를 열고 새 페이지를 만들지 않는다.

### 2.3 본문은 기존 블록 편집기를 사용한다

- 새로운 일기 전용 텍스트 엔진을 만들지 않는다.
- 기본 블록은 날짜 제목과 빈 문단 하나뿐이다.
- 사용자는 `/` 메뉴로 이미지, 인용, 체크리스트와 다른 블록을 추가할 수 있다.
- 일기 화면에서는 블록 도구를 평소에는 덜 강조해 메모처럼 편안한 인상을 준다.

### 2.4 일기와 플래너는 별도 기능이다

- 일기 볼트 지정은 `planner.mode`에 의존하지 않는다.
- 일기를 쓰기 위해 일간 플래너를 켤 필요가 없어야 한다.
- 기존 `dailyNoteTemplate: 'diary'`는 호환을 위해 당분간 읽을 수 있게 유지한다.
- 신규 일기 생성은 플래너의 사용자 지정 일간 템플릿보다 일기 기본 구조를 우선한다.
- 기존 일간 계획·포스트잇·루틴·일정 데이터는 변경하지 않는다.

## 3. 사용자 흐름

### 3.1 기존 볼트를 일기 볼트로 지정

```text
설정 → 일기
→ 일기 볼트 선택
→ 기존 볼트 목록에서 하나 선택
→ 저장
```

- 선택 즉시 폴더나 메모를 만들지 않는다.
- 사용자가 `오늘 일기 열기` 또는 날짜 선택을 실행할 때만 메모를 만든다.
- 현재 볼트를 바로 지정하는 `이 볼트를 일기 볼트로 지정` 동작도 제공할 수 있다.

### 3.2 현재 일기 볼트에서 오늘 일기 열기

```text
사이드바 일기 탭
→ 오늘 일기 열기
→ 오늘 날짜의 기존 일기 탐색
→ 있으면 열기
→ 없으면 새 메모 생성 후 빈 문단에 포커스
```

### 3.3 다른 볼트에서 오늘 일기 열기

전역 단축 진입점을 제공하는 경우 다음 순서를 지킨다.

```text
현재 페이지의 저장 완료 확인
→ 지정된 일기 볼트로 전환
→ 새 볼트의 페이지·카테고리·설정 로드 완료
→ 오늘 일기 열기 또는 생성
```

- 볼트 전환과 일기 생성을 동시에 실행하지 않는다.
- 전환 중 두 번 눌러도 같은 전환·생성 작업을 공유한다.
- 현재 페이지 저장이 실패하면 전환을 중단하고 사용자에게 알린다.

### 3.4 달력에서 과거 일기 열기

- 일기 탭의 월간 달력에서 작성된 날짜를 표시한다.
- 날짜를 누르면 해당 날짜의 일기를 열거나 생성한다.
- 미래 날짜도 사용자가 명시적으로 선택하면 생성할 수 있다.
- 일기가 없는 날짜를 달력 탐색만으로 자동 생성하지 않는다.

### 3.5 일기 볼트 변경 또는 해제

- 변경 전 현재 지정 볼트와 새 지정 볼트를 명확히 표시한다.
- 변경해도 기존 일기 메모를 이동하거나 삭제하지 않는다.
- 해제하면 공식 일기 진입점만 비활성화한다.
- 다시 같은 볼트를 지정하면 기존 `diary-day` 페이지를 그대로 인식한다.

## 4. 화면 정보 구조

### 4.1 설정 → 일기

```text
일기 기능

일기 볼트
[ 개인 일기                     ▼ ]

선택한 볼트에서만 날짜별 일기를 만들 수 있습니다.
기존 메모는 이동하거나 변경하지 않습니다.

[오늘 일기 열기]  [지정 해제]
```

상태별 표시 규칙은 다음과 같다.

| 상태 | 표시 | 허용 동작 |
|---|---|---|
| 미지정 | `일기 볼트를 선택하세요` | 기존 볼트 지정 |
| 정상 | 볼트 이름과 경로 | 오늘 열기, 변경, 해제 |
| 볼트 없음 | `지정된 볼트를 찾을 수 없습니다` | 다시 지정, 해제 |
| 저장 실패 | 오류 원인과 재시도 안내 | 재시도 |

### 4.2 지정된 볼트의 사이드바

- 기존 `계획` 탭과 독립적인 `일기` 탭을 표시한다.
- 상단에 `오늘 일기 열기`를 배치한다.
- 월간 달력에서 일기가 있는 날짜를 표시한다.
- 최근 일기 목록을 날짜 내림차순으로 표시한다.
- 일반 메모·폴더 탐색은 그대로 유지한다.

### 4.3 일반 볼트의 사이드바

- 일기 달력과 날짜별 생성 버튼을 표시하지 않는다.
- 전역 오늘 일기 단축 버튼을 제공한다면 `일기 볼트로 이동`임을 문구로 명확히 한다.
- 플래너 기능은 기존 볼트별 설정에 따라 그대로 표시한다.

### 4.4 일기 편집 화면

신규 일기의 기본 구조는 다음과 같다.

```text
# 2026-08-23 (일) 일기

[빈 문단 블록 — 생성 직후 포커스]
```

- 질문, 감정 점수, 체크 항목을 기본으로 넣지 않는다.
- 블록 추가 손잡이는 hover 또는 키보드 선택 시에만 강조한다.
- 메모 제목과 본문 날짜는 독립적이다. 제목을 바꿔도 달력 연결은 유지한다.

## 5. 데이터 모델

### 5.1 전역 일기 설정 파일

`vault_config.json`은 실행 경로와 최근 볼트를 관리하는 기존 역할만 유지한다. 일기 기능 설정은 사용하지 않는다.

새 파일을 `vaults_root`에 둔다.

```text
<vaults_root>/.diary_config.json
```

초기 형식은 다음과 같다.

```json
{
  "version": 1,
  "diaryVaultName": "개인 일기"
}
```

현재 볼트 시스템에는 영구 볼트 ID가 없으므로 1차 구현은 정규화된 볼트 이름을 참조한다.

안전 계약:

- 지정할 때 실제 `vaults_root` 아래에 존재하는 폴더인지 검증한다.
- 절대 경로나 `..`를 입력값으로 받지 않는다.
- 원자적 임시 파일 쓰기와 교체를 사용한다.
- 볼트 이름 변경 시 참조 이름도 같은 작업에서 갱신한다.
- 볼트 삭제 시 설정을 자동으로 다른 볼트에 연결하지 않는다.
- 파일이 손상되면 `미지정`으로 안전하게 읽고 원본 파일을 자동 덮어쓰지 않는다.

장기적으로 볼트에 영구 ID를 도입하면 `diaryVaultId`로 마이그레이션할 수 있다. 이번 기능만을 위해 전체 볼트 ID 마이그레이션을 먼저 수행하지 않는다.

### 5.2 일기 페이지 식별자

`Page.pageRole`을 확장한다.

```ts
pageRole?: 'postit-month' | 'diary-day'
periodKey?: string // diary-day에서는 YYYY-MM-DD
```

신규 일기 페이지 예시는 다음과 같다.

```json
{
  "id": "uuid",
  "title": "일기 2026-08-23",
  "icon": "📔",
  "pageRole": "diary-day",
  "periodKey": "2026-08-23",
  "blocks": []
}
```

탐색 우선순위:

1. `pageRole === 'diary-day' && periodKey === date`
2. 명시적으로 연결된 구형 일기 페이지
3. 없으면 신규 생성

페이지 제목만으로 신규 일기를 판별하지 않는다. 사용자가 제목을 변경할 수 있고 같은 제목의 일반 메모가 존재할 수 있기 때문이다.

### 5.3 기본 블록

```ts
[
  { type: 'heading1', content: '2026-08-23 (일) 일기' },
  { type: 'paragraph', content: '' },
]
```

- 모든 블록은 기존 `Block` 타입과 저장 경로를 사용한다.
- 일기 전용 블록 타입을 추가하지 않는다.
- 이미지와 첨부 파일도 기존 페이지 동작을 따른다.

## 6. API 설계

### 6.1 일기 설정 조회

```http
GET /api/settings/diary
```

응답 예시:

```json
{
  "version": 1,
  "diaryVaultName": "개인 일기",
  "status": "ready",
  "availableVaults": ["기본", "업무", "개인 일기"]
}
```

`status`는 `unconfigured`, `ready`, `missing` 중 하나다.

### 6.2 일기 볼트 지정 또는 해제

```http
PUT /api/settings/diary
Content-Type: application/json

{ "diaryVaultName": "개인 일기" }
```

해제:

```json
{ "diaryVaultName": null }
```

검증 규칙:

- 문자열은 공백 제거 후 현재 볼트 목록의 이름과 완전히 일치해야 한다.
- 존재하지 않는 볼트는 `404`로 거절한다.
- 잘못된 이름과 경로 이탈 시도는 `400`으로 거절한다.
- 저장 실패는 기존 설정을 보존하고 오류를 반환한다.

### 6.3 일기 생성 위치

일기 페이지 생성은 기존 페이지 API와 `pageStore`를 사용한다. 백엔드가 비활성 볼트에 직접 페이지를 쓰는 별도 API는 만들지 않는다.

```text
프론트엔드가 지정 볼트 확인
→ 필요하면 기존 switch-vault API로 전환
→ 새 볼트 로드 완료
→ 기존 pageStore 경로로 페이지 생성·저장
```

이렇게 하면 현재 활성 볼트라는 단일 쓰기 경계를 유지하고, 서로 다른 볼트의 인덱스를 한 요청에서 동시에 수정하지 않는다.

## 7. 프론트엔드 구조

### 7.1 신규 모듈 후보

```text
src/store/diaryStore.ts
src/lib/diaryNotes.ts
src/components/diary/DiaryPanel.tsx
src/components/settings/tabs/DiaryTab.tsx
```

책임 분리:

- `diaryStore`: 전역 일기 볼트 설정의 로드·저장·상태 관리
- `diaryNotes`: 날짜 검증, 기존 일기 탐색, 생성 중복 방지, 볼트 전환 후 열기
- `DiaryPanel`: 오늘 버튼, 달력, 최근 일기 목록
- `DiaryTab`: 볼트 지정·변경·해제 UI

### 7.2 핵심 공개 함수

```ts
openOrCreateDiary(dateStr: string): Promise<string | null>
```

계약:

1. 날짜 형식을 검증한다.
2. 지정된 일기 볼트가 존재하는지 확인한다.
3. 현재 볼트가 다르면 저장 완료 후 지정 볼트로 전환한다.
4. 전환 세대가 최신인지 확인한다.
5. `pageRole`과 `periodKey`로 기존 일기를 찾는다.
6. 없으면 페이지를 한 번만 생성한다.
7. 기본 블록을 생성된 페이지 ID에 적용한다.
8. 즉시 저장이 성공한 뒤 빈 문단에 포커스한다.

### 7.3 동시 실행 방지

진행 중 작업 키는 일기 볼트와 날짜를 함께 사용한다.

```ts
`${diaryVaultName}:${dateStr}`
```

- 같은 창에서 버튼을 연속으로 눌러도 같은 Promise를 공유한다.
- 볼트 전환 중 이전 요청의 응답이 늦게 도착해 현재 상태를 덮지 않도록 generation 토큰을 사용한다.
- 다른 앱 창까지 완전한 중복 방지가 필요하면 백엔드 인덱스 쓰기에 `(pageRole, periodKey)` 고유 검사를 추가한다.

## 8. 기존 기능과 호환

### 8.1 현재 자유 일기 템플릿

현재 `planner.dailyNoteTemplate === 'diary'`는 `일간 노트 YYYY-MM-DD` 페이지에 날짜 제목과 빈 문단을 만든다.

전환 원칙:

- 기존 설정값을 즉시 삭제하지 않는다.
- 기존 페이지를 자동으로 `diary-day`로 바꾸지 않는다.
- 지정된 일기 볼트에서만 `기존 자유 일기 연결` 도구를 제공한다.
- 연결 전 후보 페이지 수와 날짜를 보여주고 사용자가 확인한 경우에만 역할 메타데이터를 추가한다.
- 블록 내용과 제목은 변경하지 않는다.

### 8.2 기존 일간 노트와 플래너

- `standard`와 `postit` 템플릿을 유지한다.
- `openOrCreateDailyNote()`의 기존 플래너 진입점을 유지한다.
- `openOrCreateDiary()`는 별도 함수로 분리한다.
- 일기 볼트에 남아 있는 플래너 설정과 데이터는 보존하지만, 사이드바에서는 계획 탭과 `오늘 일정 보기`를 숨겨 일기 작성 흐름에 집중한다.
- 전용 일기 볼트를 지정하기 전에 플래너의 `자유 일기` 템플릿으로 작성한 볼트도 같은 집중 화면을 사용하며, 기존 `일간 노트 YYYY-MM-DD` 메모를 날짜별 목록에 그대로 표시한다.

### 8.3 일반 메모

- 일반 페이지 생성, 편집, 삭제, 이동, 휴지통과 복원 동작을 변경하지 않는다.
- `일기`, 날짜 또는 같은 아이콘을 사용하는 일반 페이지를 제한하지 않는다.
- 공식 일기 여부는 제목이나 아이콘이 아니라 메타데이터로만 판정한다.

## 9. 오류와 예외 처리

| 상황 | 처리 |
|---|---|
| 일기 볼트 미지정 | 생성하지 않고 설정 이동 안내 |
| 지정 볼트 삭제·외부 이동 | `missing` 표시, 자동 대체 금지 |
| 지정 볼트 이름 변경 | rename API에서 설정 참조 함께 갱신 |
| 외부 파일 탐색기에서 이름 변경 | `missing` 표시 후 사용자가 다시 지정 |
| 현재 페이지 저장 실패 | 볼트 전환과 일기 열기 중단 |
| 볼트 전환 실패 | 현재 볼트 유지, 오류 표시 |
| 같은 날짜 중복 페이지 발견 | 가장 오래된 정상 역할 페이지를 열고 중복 경고 |
| 신규 페이지 저장 실패 | 로컬 초안을 보존하고 저장 실패 표시 |
| 설정 파일 손상 | 읽기 실패를 표시하고 자동 덮어쓰기 금지 |
| 잘못된 날짜 | 아무 페이지도 만들지 않음 |

## 10. 개인정보와 안전 계약

- 일기 볼트 지정은 접근 제어 또는 암호화가 아니다.
- 기존 페이지 PIN은 앱 내부 편집 제한이며 파일 암호화로 표현하지 않는다.
- 지정·변경·해제 과정에서 페이지나 볼트 폴더를 자동 이동·삭제하지 않는다.
- 테스트는 임시 `vaults_root`에서 수행하고 실제 사용자 일기 볼트에 샘플 페이지를 만들지 않는다.
- `vault_config.json`을 초기화하거나 테스트 값으로 저장하지 않는다.
- 내보내기와 클라우드 동기화에는 기존 페이지와 같은 규칙을 적용한다.

## 14. 권장 첫 구현 단위

첫 구현은 P0~P3으로 제한한다.

```text
전역 일기 볼트 지정
→ 지정 볼트에서만 일기 탭 노출
→ 날짜별 diary-day 메모 생성
→ 기존 블록 편집기로 작성
```

달력, 다른 볼트에서 자동 전환, 기존 자유 일기 연결은 기본 생성과 저장 안정성이 확인된 뒤 P4~P5로 진행한다.

이 순서를 따르면 첫 배포에서 가장 중요한 계약인 `한 볼트에서만, 날짜별 메모 한 장에, 블록으로 자유롭게 작성`을 작은 범위로 검증할 수 있다.

### P0~P3 구현 결과 — 2026-08-23

- 전역 일기 설정은 `vaults_root/.diary_config.json`에 원자적으로 저장한다.
- 설정 → 볼트 기능에서 기존 볼트 하나를 일기 볼트로 지정하거나 해제할 수 있다.
- 지정 볼트에서만 사이드바 하단의 독립 `📔 일기` 버튼을 표시한다.
- 일기 페이지는 `pageRole: 'diary-day'`와 `periodKey: YYYY-MM-DD`로 식별한다.
- 오늘 일기는 날짜 제목과 빈 문단 블록으로 생성하며, 기존 블록 편집기를 그대로 사용한다.
- 플래너·포스트잇 허브와 일기 허브를 별도 사이드바 상태로 유지한다.
- 볼트 이름 변경 시 전역 일기 참조도 함께 갱신한다.
- 기존 자유 일기 템플릿과 기존 일간 노트는 변환하거나 삭제하지 않았다.
- 자동 검증: TypeScript, 변경 파일 ESLint, 일기 식별 Node 테스트 2건, 관련 백엔드 테스트 12건 통과.
- 개발 서버의 백엔드가 이전 프로세스로 실행 중이면 새 API가 404를 반환하므로 재시작 후 실제 UI 검증이 필요하다.
