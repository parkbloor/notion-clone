# 개발상황 일지

## 2026-08-01 — 메모 원본 이미지 다운로드·드래그앤드롭 및 Windows 패키지 갱신

### 이미지 다운로드 기능

- 이미지 업로드 응답과 이미지 블록 데이터에 원본 파일명·크기·MIME 형식을 보존하도록 확장했다.
- 이미지 블록의 각 이미지에서 원본 파일명으로 개별 다운로드할 수 있는 버튼을 추가했다.
- 페이지 내 모든 이미지를 한 번에 ZIP으로 내려받는 메뉴를 페이지 내보내기 메뉴에 추가했다.
- 현재 `images[]` 형식뿐 아니라 이전 단일 이미지 형식과 중첩 블록의 이미지도 다운로드 대상에 포함한다.
- ZIP 안에서 같은 이름이 겹치면 파일명을 자동으로 구분하며, Windows 예약 이름(`CON`, `PRN`, `AUX`, `NUL`, `COM1`~`COM9`, `LPT1`~`LPT9`)도 안전한 이름으로 변환한다.

### 이미지 드래그앤드롭

- 한 이미지 블록에 여러 이미지가 있을 때 전용 핸들로 순서를 바꿀 수 있도록 했다.
- Electron 앱에서 이미지를 Windows 탐색기나 바탕화면으로 끌어내 파일로 복사할 수 있도록 네이티브 드래그를 연결했다.
- 드래그할 파일은 활성 볼트의 `/static/` 이미지인지 확인하고, 볼트 밖 경로나 임의 URL은 거부한다.
- 드래그용 임시 복사본은 앱 시작·종료 시 정리하며, 같은 원본을 다시 드래그할 때 이전 복사본을 안전하게 교체한다.

### 검토 중 발견한 문제와 수정

- 전체 이미지 ZIP을 메모리에 한꺼번에 만들면 큰 이미지가 많은 페이지에서 메모리 사용량이 급증하는 문제를 발견했다.
  - ZIP을 임시 파일에 스트리밍하고 응답 완료 후 자동 삭제하도록 수정했다.
  - 20MB 임의 데이터 기준 ZIP 생성 최대 추가 메모리가 약 22.1MB에서 약 0.7MB로 감소했다.
- 원본 파일명이 Windows 예약 이름이면 다운로드 후 사용할 수 없는 파일이 생성될 수 있어 안전한 접두사를 붙이도록 수정했다.
- Electron 드래그 임시 파일이 비정상 종료 뒤 남거나 같은 이미지 재드래그 시 충돌할 가능성을 보완했다.

### 자동 검증

- 백엔드 전체 단위 테스트 16개 통과
  - 원본 바이트·파일명 다운로드
  - 레거시·중첩 이미지 수집
  - 중복 파일명과 Windows 예약 이름 처리
  - ZIP 임시 파일 응답 후 삭제
  - 이미지 업로드 메타데이터
- `npx.cmd tsc --noEmit` 통과
- 변경 파일 대상 ESLint 통과
- `node --check electron/main.js` 및 `node --check electron/preload.js` 통과
- `git diff --check` 통과(CRLF 변환 경고만 존재)
- Electron 드래그 헬퍼의 정상 경로·파일 바이트·동일 원본 교체·범위 제한 정리를 격리 검증했다.

  - 압축 해제 실행판: `dist-electron/win-unpacked/Notion Clone.exe`
- 설치 프로그램 생성 시점: 2026-08-01 12:53:23 (KST), 크기: 124,792,382 bytes.
- 설치 프로그램 SHA-256: `11FA437CCE11799530C196E8B6D43748D18C37F962CA5268CFED2A9587F864ED`.
- 압축 해제 실행판을 직접 실행해 백엔드 `http://127.0.0.1:8000/api/pages`와 화면 서버 `http://127.0.0.1:3000`이 모두 HTTP 200을 반환하는 것을 확인했다.
- 검증 후 실행한 앱과 자식 서버가 모두 종료되고 8000/3000 포트가 닫힌 것을 확인했다.

## 2026-07-30 — 볼트 데이터 안전성 강화 및 Windows 패키지 빌드

### 완료한 안정화 작업

- 페이지·카테고리 이동 시 실제 폴더 경로와 이미지 URL을 함께 갱신하도록 보완했다.
- 저장·이동·삭제·정렬·휴지통 변경을 백엔드 단일 쓰기 잠금으로 직렬화해, 저장 요청과 폴더 이동이 섞이는 경쟁 상태를 방지했다.
- 페이지 `revision` 기반 낙관적 동시성 검사를 추가했다.
  - 다른 창의 최신 저장이 있으면 오래된 저장은 HTTP 409으로 거부한다.
  - 로컬 편집 내용은 유지하고, 충돌 안내를 표시한다.
- 페이지·카테고리 이동 중 URL 갱신이나 인덱스 저장에 실패하면 원래 폴더와 이미지 URL로 롤백한다.
- `_logs/pending_moves.json` 이동 저널을 추가했다.
  - 이동 전 원본/대상/URL 접두사/예상 인덱스 상태를 기록한다.
  - 앱 시작 시 완료되지 않은 이동을 인덱스와 대조해 확정하거나 원복한다.
- 카테고리·메모 정렬 또는 카테고리 이동의 서버 저장 실패 시 클라이언트가 서버 상태를 즉시 다시 불러오도록 했다.
- 휴지통의 실물 폴더가 없는 경우 인덱스만 복원하지 않고 오류로 중단하도록 했다.
- 무결성 검사 범위를 활성 메모에서 휴지통·버전 히스토리의 이미지 참조까지 확장했다.
- 오류 로그는 5MB 초과 시 최근 2,000개 JSONL 항목만 유지하도록 했다.

### 자동 검증

- 백엔드 안전성 테스트 10개 통과
  - 페이지/카테고리 이동 및 이미지 URL 갱신
  - 저장 충돌 거부
  - 미완료 이동 저널의 시작 시 롤백
  - 이미지 업로드 안전성
  - 활성·히스토리 이미지 무결성 검사
  - 오류 로그 보존 정책
- `npx.cmd tsc --noEmit` 통과
- `npm.cmd run lint` 통과 (경고 0개)
- `npm.cmd run build:next` 통과 (제한 없는 네트워크 환경에서 Google Fonts 포함)

### Windows 패키지

- `npm.cmd run build:all`은 2분 실행 제한으로 완료 상태를 받지 못했지만, Next.js와 PyInstaller 백엔드 산출물은 생성됐다.
- 이어서 `npm.cmd run build:electron`을 완료했다.
- 생성 산출물:
  - 설치 프로그램: `dist-electron/Notion Clone Setup 0.1.0.exe`
  - 압축 해제 실행판: `dist-electron/win-unpacked/Notion Clone.exe`
- 설치 프로그램 생성 시점: 2026-07-30 21:31 (KST), 크기: 124,783,324 bytes.
- 패키지 실행을 자동으로 짧게 점검했으나 프로세스가 종료 코드 0으로 종료되어 8000/3000 포트 응답은 확인하지 못했다. 따라서 설치 파일 생성은 완료됐지만, 실제 GUI 기동 확인은 별도 수동 점검이 필요하다.

### 운영 메모

- 백엔드 변경을 반영하려면 개발 서버를 재시작해야 한다.
- 오류·복구 기록은 활성 볼트의 `_logs/operation_log.jsonl`에서 확인한다.
- 미완료 이동 기록은 활성 볼트의 `_logs/pending_moves.json`에 남으며, 다음 백엔드 시작 시 자동 처리된다.
