## 2. 데이터 모델 변경

### 2-1. `src/types/block.ts` — `PlanEvent` 확장

```ts
export interface SubTask {
  id:   string
  text: string
  done: boolean
}

export interface PlanEvent {
  id:       string
  title:    string
  start:    string
  end:      string
  color:    string
  done:     boolean
  clockIn?:  string
  clockOut?: string
  elapsed?:  number
  // ── 신규 필드 ──────────────────────────
  log?:      string      // 실제 수행 기록 (자유 텍스트)
  subtasks?: SubTask[]   // 서브태스크 체크리스트
  energy?:   number      // 에너지/집중도 레벨 (1~5)
}
```

### 2-2. `PlannerData` — 일일 회고 필드 추가

```ts
export interface PlannerData {
  eventsByDate: Record<string, PlanEvent[]>
  reviewByDate?: Record<string, string>   // 'YYYY-MM-DD' → 하루 회고 텍스트
}
```

## 3. UI 컴포넌트 변경

### 3-1. `DayPlannerBlock.tsx` — 우측 패널 교체

| 항목 | 현재 | 변경 후 |
|------|------|---------|
| 상태 | 없음 | `selectedEventId: string \| null` 추가 |
| 패널 | 이벤트 목록 (w-52, 읽기전용) | 상세 기록 패널 (w-64, 편집 가능) |
| 이벤트 클릭 | `openEdit(ev)` — 수정 팝업 열기 | `setSelectedEventId(ev.id)` — 우측 패널 전환 |
| 타임테이블 이벤트 블록 클릭 | 동일 | 동일 (수정 팝업 → 상세 패널로 전환) |

#### 우측 패널 구조 (선택된 이벤트 없을 때)
- 기존 이벤트 목록 UI 유지 (클릭하면 상세 패널로 전환)
- 하단에 **오늘 하루 회고** 텍스트 영역 고정

#### 우측 패널 구조 (이벤트 선택됨)
```
┌─ 헤더 ─────────────────────────────────┐
│  ← 뒤로  🔵  09:00–10:00 코드리뷰       │
├─────────────────────────────────────────┤
│  상태바                                  │
│  [✓ 완료 토글]  [⚡⚡⚡ 에너지]           │
│  계획: 1h 00m  /  실제: 1h 23m           │
├─────────────────────────────────────────┤
│  📝 실제 기록                            │
│  ┌─────────────────────────────────┐   │
│  │ (textarea — 자동저장)           │   │
│  └─────────────────────────────────┘   │
├─────────────────────────────────────────┤
│  ☐ 서브태스크                    [+ 추가] │
```

## 4. 기능 상세 명세

### F-1. 이벤트 상세 기록 패널

| 항목 | 동작 |
|------|------|
| 진입 | 타임테이블 이벤트 블록 클릭 OR 이벤트 목록 행 클릭 |
| 종료 | `←` 뒤로 버튼 클릭 → 이벤트 목록 뷰로 복귀 |
| 선택 강조 | 타임테이블에서 선택된 이벤트 블록에 `ring-2` 하이라이트 |
| 저장 방식 | textarea `onChange` → 300ms 디바운스 → `updateBlock` (자동저장) |

### F-2. 서브태스크 (체크리스트)

| 항목 | 동작 |
|------|------|
| 추가 | `+ 추가` 버튼 또는 빈 input에서 `Enter` |
| 완료 토글 | 체크박스 클릭 |
| 삭제 | 행 hover 시 `×` 버튼 표시 |
| 완료율 표시 | 헤더에 `2/3` 형태로 서브태스크 완료율 표시 |

### F-3. 소요시간 비교

| 항목 | 계산 방법 |
|------|-----------|
| 계획 시간 | `timeToMin(end) - timeToMin(start)` |
| 실제 시간 | 기존 `elapsed` 필드 (Clock in/out 누적값) |
| 표시 | 계획 1h 00m / 실제 1h 23m (+23m 초과) |
| 초과 시 | 빨간색 텍스트로 강조 |

### F-4. 에너지 레벨

| 항목 | 동작 |
|------|------|
| UI | ⚡ × 5개 — 클릭으로 1~5 선택, 0이면 미선택 상태 |
| 저장 | `energy: number` → `PlanEvent`에 즉시 저장 |
| 표시 위치 | 상태바 우측 |

### F-5. 완료율 요약 바 (헤더 영역)

우측 패널 최상단(이벤트 목록 뷰)에 항상 표시:

```
오늘 진행률  ████████░░  3 / 7 완료
총 계획 5h 30m  |  완료 3h 15m  |  남은 2h 15m
```

- `done: true` 이벤트 수 / 전체 이벤트 수
- 완료된 이벤트의 계획 시간 합산

### F-6. 일일 회고 섹션

| 항목 | 동작 |
|------|------|
| 위치 | 우측 패널 하단 (이벤트 목록 뷰일 때 항상 표시) |
| 저장 | `reviewByDate[date]` — 300ms 디바운스 자동저장 |
| 힌트 | placeholder: "오늘 하루를 돌아보며..." |

### F-7. 기록 있는 날짜 표시

| 항목 | 동작 |
|------|------|
| 조건 | `log`가 있거나 `subtasks.length > 0`이거나 `reviewByDate[date]` 있음 |
| 표시 | 날짜 네비게이션 버튼 아래 작은 주황 dot (●) |

## 6. 구현 순서

1. **타입 확장** — `block.ts` 수정 (SubTask, PlanEvent, PlannerData)
2. **상태 추가** — `DayPlannerBlock`에 `selectedEventId` state
3. **타임테이블 클릭 연결** — 이벤트 블록 onClick → `setSelectedEventId`
4. **이벤트 목록 뷰 개선** — 완료율 요약 바 + 회고 섹션 추가
5. **상세 기록 패널 구현** — 로그 textarea + 서브태스크 + 에너지 + 소요시간 비교
6. **자동저장 연결** — 디바운스 `updateBlock`
7. **날짜 dot 표시** — 기록 여부 판별 로직
8. **i18n 문자열** — ko.ts / en.ts

## 7. 스펙 요약 (한눈에)

```
PlanEvent 신규 필드
  log?:      string          // 자유 텍스트 기록
  subtasks?: SubTask[]       // 서브태스크 배열
  energy?:   number (1~5)    // 집중도

PlannerData 신규 필드
  reviewByDate?: Record<string, string>  // 일일 회고

우측 패널 상태
  mode: 'list' | 'detail'
  selectedEventId: string | null

detail 모드 구성 요소
  ① 헤더 (뒤로 + 이벤트 제목/시간/색상)
  ② 상태바 (완료 토글 + 에너지 + 소요시간 비교)
  ③ 로그 textarea (자동저장)
  ④ 서브태스크 리스트
  
list 모드 구성 요소 (기존 + 추가)
  ① 완료율 요약 바 (신규)
  ② 이벤트 목록 (기존, 클릭 시 detail 전환)
  ③ 일일 회고 textarea (신규, 하단 고정)
```
