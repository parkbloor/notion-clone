## 1. 현재 기준선

- `docs/01`~`14`는 현재 구현을 기준으로 정렬 작업이 진행되었다.
- `docs/03_Types.md`는 `src/types/block.ts`와 정렬되어 있다.
- 2026-06-22 기준 `npx.cmd tsc --noEmit`은 통과했다.
- `npm.cmd run lint`는 오류 없이 끝나지만 경고 91개가 남아 있다.
- 작업 트리에 UI, 플래너, 백엔드, 문서 변경이 함께 있으므로, 이 계획의 각 단계는 독립적으로 검증하고 작은 단위로 마감한다.

## 2. 우선순위와 진행 순서

```
P0 리디자인 화면 QA
  → P1 QA에서 발견한 회귀 수정 및 관련 lint 정리
    → P2 Day Planner 저장 안정화 리팩터링
      → P3 청사진 및 계획 문서 마감

```

P0~P3을 모두 새 기능보다 우선한다. P0에서 저장·편집 회귀가 발견되면 P1보다 먼저 해당 회귀를 수정한다.

## P0. 리디자인 화면 QA

### 목표

`docs/redesign-plan.md`에 반영된 warm-moss 디자인이 실제 앱에서 기존 편집·탐색 흐름을 깨지 않는지 확인한다.

### 확인 범위

| 화면 | 핵심 확인 항목 | 관련 파일 |
|---|---|---|
| 앱 시작·테마 | 라이트/다크/프리셋 변경 즉시 반영, 새로고침 후 유지 | `page.tsx`, `globals.css`, `settingsStore.ts`, `AppearanceTab.tsx` |
| 사이드바 | 페이지 선택, 폴더 펼침, 드래그, 인라인 메뉴, 스크롤 | `CategorySidebar.tsx`, `src/components/sidebar/*` |
| 상단 탭 | 탭 전환·닫기·저장 단축키, 좁은 화면 가로 스크롤 | `TabBar.tsx` |
| 편집 영역 | 제목·본문·특수 블록 입력, 포커스 링, 긴 문서 스크롤 | `PageEditor.tsx`, `Editor.tsx`, `globals.css` |
| 우측 패널·하단 바 | 패널 열기/닫기·독립 스크롤, 단어 수·폭 조절 | `RightPanel.tsx`, `BottomBar.tsx` |
| 부가 위젯 | 포모도로 위치·조작, 캘린더 오버레이의 날짜 이동 | `PomodoroWidget.tsx`, `CalendarOverlay.tsx` |

### 실행 절차

1. 개발 서버에서 라이트/다크 모드를 각각 확인한다.
2. 빈 페이지와 블록이 많은 기존 페이지를 열어 위 표의 흐름을 한 번씩 수행한다.
3. 브라우저 폭을 좁혀 사이드바, 탭, 우측 패널의 겹침·잘림을 확인한다.
4. 각 발견 사항을 **재현 절차 / 기대 결과 / 실제 결과 / 관련 파일**로 기록한다.
5. 확인된 항목만 `docs/redesign-plan.md`의 완료 체크로 갱신한다.

### 완료 기준

- 테마 전환, 페이지 전환, 입력, 저장, 패널 조작에서 기능 회귀가 없다.
- 좁은 폭에서도 탭·패널이 서로 가리거나 주요 버튼이 화면 밖으로 사라지지 않는다.
- 체크리스트는 추측이 아니라 실제 화면 확인 결과를 반영한다.

### 실행 기록 — 2026-06-22

| 항목 | 결과 | 근거 |
|---|---|---|
| 개발 서버 | 통과 | Next.js `:3000`, FastAPI `:8000`이 모두 HTTP 200 응답 |
| 데스크톱 레이아웃 | 통과 | 사이드바, 긴 일간 노트, 우측 목차 패널, 하단 바, 포모도로가 동시에 표시되고 겹침 없음 |

| 사이드바 탐색 | 통과 | 기존 페이지 선택 후 제목·탭이 정상 전환 |
| 우측 패널 | 통과 | 목차에서 백링크 탭으로 정상 전환 |

## P1. 회귀 수정 및 lint 정리

### 목표

P0에서 확인된 문제를 좁은 패치로 고치고, 이번 변경과 직접 닿는 경고를 우선 제거한다.

### 원칙

- 전체 91개 경고를 한 번에 없애려 하지 않는다. 기능 변경과 무관한 대량 포맷팅은 피한다.
- 우선순위는 `react-hooks/exhaustive-deps`처럼 동작 오류로 이어질 수 있는 경고, 그 다음 미사용 import/변수, 마지막으로 이미지 최적화 권고다.
- `eslint --fix`는 변경 파일을 검토한 뒤 제한적으로만 사용한다.

### 우선 점검 대상

1. `page.tsx`, `Editor.tsx`, `BottomBar.tsx`, `PropertyPanel.tsx`의 Hook 의존성 경고
2. 리디자인에서 수정된 `TabBar.tsx`, `CategorySidebar.tsx`, `RightPanel.tsx`, `PomodoroWidget.tsx`, `AppearanceTab.tsx`의 미사용 코드
3. Day Planner와 연결되는 `QuarterlyPlannerBlock.tsx`, `YearlyPlannerBlock.tsx`의 `plannerRoutines` 의존성 경고

### 완료 기준

- 수정한 파일에서 새 lint 오류가 없다.
- `npm.cmd run lint`와 `npx.cmd tsc --noEmit`을 다시 통과한다.
- P0에서 보고된 회귀의 재현 절차가 해결됐음을 확인한다.

### 실행 기록 — 2026-06-22

- 리디자인 관련 8개 파일의 lint 경고를 **23개 → 0개**로 정리했다.
- 사용하지 않는 설정 import/구독 값, 포모도로의 잔여 색상 변수, 만료된 eslint 억제 주석을 제거했다.
- `BottomBar`는 페이지 블록이 없을 때 매 렌더마다 새 배열을 만들지 않도록 `useMemo` 의존성을 안정화했다.
- 전체 lint 경고는 **91개 → 68개**로 감소했다. 남은 경고는 이번 정리 범위 밖의 기존 파일에 있다.
- `npx.cmd tsc --noEmit`, `npm.cmd run lint`, `git diff --check`을 통과했다.

P1을 완료했다.

## P2. Day Planner 저장 안정화 리팩터링

### 목표

Day Planner의 UI 동작은 유지하면서 저장 경로와 타입 경계를 명확히 한다.

### 작업 단위

1. **드래그·리사이즈 로직 분리**
   - `DayPlannerBlock.tsx`의 좌표 계산, preview 상태, 포인터 이벤트를 `PlannerTimeline` 또는 전용 hook으로 분리한다.
   - 렌더링 컴포넌트에는 표시와 이벤트 연결만 남긴다.

2. **아카이브 API 타입 구체화**
   - `plannerApi.getArchive/appendArchive`의 `unknown[]` 경계를 `Record<string, PlanEvent[]>`로 좁힌다.
   - 순환 import가 생기지 않도록 공유 타입은 `src/types/block.ts`에 유지한다.

3. **JSON 업데이트 공통화**
   - 이벤트, 회고, 아카이브의 읽기-수정-저장 흐름을 공용 updater로 모은다.
   - 빠른 연속 조작에서도 이전 저장 결과가 최신 상태를 덮어쓰지 않는지 확인한다.

4. **설정 용어 재검토**
   - `plannerStartHour`가 초기 스크롤이 아니라 표시 시작 시각이라는 점을 설정 UI와 번역 문구에 명시한다.

### 검증 시나리오

- 이벤트 생성·이동·시간 조절·삭제 후 새로고침해도 값이 유지된다.
- 같은 날짜의 이벤트와 회고를 연속 편집해도 서로 유실되지 않는다.
- 미예약 이벤트가 자정 일정으로 저장되지 않는다.
- 아카이브 조회/추가의 응답 데이터가 타입 검사로 보호된다.

### 완료 기준

- 공용 타임라인과 Day Planner의 책임 경계가 코드에서 명확하다.
- 위 시나리오와 `npm.cmd run lint`, `npx.cmd tsc --noEmit`이 통과한다.

### 실행 기록 — 2026-06-22

- `plannerApi.getArchive/appendArchive`의 아카이브 이벤트 타입을 `Record<string, PlanEvent[]>`로 구체화했고, 화면 컴포넌트의 타입 단언을 제거했다.
- `DayPlannerBlock`에 `readLatestPlannerData()`와 `commitPlannerData()`를 추가했다. 이벤트 저장, 일일 회고 저장, 루틴 수동 적용, 날짜 이동 중 자동 루틴 적용, 단일 이벤트 필드 수정이 최신 JSON을 공통 경로로 갱신한다.
- 90일 초과 이벤트 분리와 아카이브 전송도 공통 커밋 함수 안으로 이동했다. 날짜 이동 경로의 별도 `fetch()` 호출은 제거했다.
- `DayPlannerBlock.tsx` 및 `api.ts` lint, `npx.cmd tsc --noEmit`, `backend/routers/planner.py` 컴파일, `git diff --check`을 통과했다.
- `planner/usePlannerEventDrag.ts`로 일정의 드래그·리사이즈 상태, 포인터 리스너, 클릭 억제 처리를 분리했다. `DayPlannerBlock`에는 화면 렌더링과 콜백 연결만 남겼다.
- `DayPlannerBlock.tsx`, 새 hook, `PlannerTimeline.tsx`의 lint와 `npx.cmd tsc --noEmit`, `git diff --check`을 통과했다.
- 실제 Day Planner에서 테스트 일정을 생성하고 시간을 수정했다. 새로고침 후 변경된 일정이 유지되는 것과 삭제 후 일정이 남지 않는 것을 확인했으며, 브라우저 콘솔 오류도 없었다. 테스트 일정은 삭제 완료했다.
- 자동화 환경의 타임라인 스크롤 좌표가 포인터 좌표와 일치하지 않아 드래그·리사이즈의 실제 포인터 동작은 수동 확인이 남아 있다. 구현·정적 검증·저장 검증은 완료했다.
- 실제 확인에서 드래그/리사이즈 후 새 일정 폼이 열리는 회귀가 보고됐다. 일정 카드에서 버블된 click을 빈 타임라인 click으로 처리하지 않고, mouseup 직후 합성 click도 한 번만 소비하도록 보완했다.
- `plannerStartHour`/`plannerEndHour`는 이미 “타임라인 시작/종료 시각”으로 표기되고 설명도 “표시 시간대”로 명시돼 있어 문구 변경은 불필요했다.
